1Clases y constructores

El constructor primario va en la cabecera de la clase. Con val o var delante, el parámetro se convierte además en propiedad.

Gracias a los valores por defecto y a los argumentos con nombre, casi nunca hacen falta constructores secundarios ni sobrecargas, como en Java.

2Propiedades

valsolo lectura: genera un getter
varlectura y escritura: getter y setter
get() = ...getter propio; sin field, la propiedad no guarda nada
set(v) { field = v }setter propio; field es el valor guardado
private setpública para leer, privada para escribir
lateinit varno nula, pero se inicializa después; leerla antes lanza UninitializedPropertyAccessException
by lazy { }se calcula una sola vez, al primer acceso
const valconstante de tipo básico o String

Dentro del setter usa field, no el nombre de la propiedad: nombre = valor volvería a llamar al setter, y así hasta un StackOverflowError.

3Visibilidad

publicdesde cualquier sitio. Es el valor por defecto
internaldesde el mismo módulo (el mismo proyecto de Gradle o Maven)
protecteddesde la clase y sus hijas (no desde el mismo paquete, como en Java)
privatedesde la clase; si está en el nivel superior, desde el mismo fichero

4Herencia: open y override

En Kotlin las clases y los métodos son finales por defecto. Hay que marcar con open lo que se permite heredar o sobrescribir, y con override lo que se sobrescribe.

open classse puede heredar
open fun / open valse puede sobrescribir
overrideobligatorio al sobrescribir (no es una anotación opcional)
super.metodo()llama a la versión del padre
is !iscomo instanceof, con conversión automática
as as?conversión; as? da null en vez de excepción
Anyla raíz de todas las clases (el Object de Java)

5Clases abstractas e interfaces

Al heredar de una clase se ponen paréntesis (se llama a su constructor): : Figura(). Las interfaces van sin paréntesis: : Dibujable.

6data class

Para clases que sobre todo guardan datos. Kotlin genera equals, hashCode, toString, copy y la desestructuración a partir de las propiedades del constructor primario.

Constructor primarioal menos un parámetro, todos con val o var
Propiedades declaradas en el cuerpono entran en equals, toString ni copy
No puede serabstract, open, sealed ni inner
Equivalente en Javaun record (ver POO avanzada)

Usa val siempre que puedas: un objeto inmutable se "modifica" con copy y no da sorpresas si se comparte o se usa como clave.

8sealed: jerarquías cerradas

Una clase o interfaz sealed solo puede tener las hijas declaradas en su mismo paquete y módulo. El compilador las conoce todas, así que un when puede comprobar que no falta ninguna. Es como un enum cuyos casos llevan datos distintos.

Si mañana se añade Resultado.SinConexion, todos los when que no lo traten dejan de compilar: el compilador te dice dónde tienes que tocar.

9object y companion object

object Nombresingleton con nombre
companion objectmiembros de la clase, no de cada objeto: Clase.metodo()
object : Tipo { }objeto anónimo que hereda o implementa algo
@JvmStaticpara que desde Java se vea como un static de verdad

Para funciones sueltas no hace falta ninguna clase: en Kotlin se pueden declarar funciones y propiedades en el nivel superior del fichero.

10Funciones de extensión

Añaden métodos a una clase que no es tuya (incluso String o List) sin heredar de ella. Dentro, this es el objeto sobre el que se llama.

Las extensiones no modifican la clase ni ven sus miembros private: son funciones normales con una sintaxis cómoda. Gran parte de la librería de Kotlin (map, filter, let...) son extensiones.
