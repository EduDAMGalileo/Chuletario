Imagen frente a contenedor

Una imagen es la plantilla de solo lectura (como una clase); un contenedor es una instancia en ejecución de esa imagen (como un objeto). De una imagen salen muchos contenedores.

Contenedor frente a máquina virtual

Contenedorcomparte el núcleo del sistema; ligero, arranca en segundos
Máquina virtualemula un sistema entero; pesada, arranca en minutos

1Qué es Docker

Docker empaqueta una aplicación y sus dependencias en un contenedor: una unidad aislada que se ejecuta igual en tu portátil, en un servidor o en la nube. Acaba con el «en mi máquina funciona».

Imagenplantilla de solo lectura con la app y su entorno
Contenedoruna imagen en ejecución
Dockerfilereceta de texto para construir una imagen
Registroalmacén de imágenes (Docker Hub)
Volumenalmacenamiento persistente fuera del contenedor

Un contenedor comparte el núcleo de Linux del anfitrión, por eso es tan ligero. Para probar Linux o Docker en sí, mira Linux.

2Primer contenedor

docker run hace tres cosas si hace falta: descarga la imagen, crea el contenedor y lo arranca. La primera vez baja la imagen; después ya está en caché.

3Imágenes

nombre:etiquetanginx:1.27; sin etiqueta, se usa latest
Capasuna imagen son capas apiladas; se reutilizan entre imágenes
Docker Hubel registro público por defecto (hub.docker.com)

Cuidado: latest no significa «la última»: es solo la etiqueta por defecto y puede quedarse anticuada. En producción, fija una versión concreta.

En -p anfitrión:contenedor, el primero es el puerto de tu máquina y el segundo el que expone el programa dentro del contenedor.

6Entrar, logs e inspección

docker exec -it <nombre> bash (o sh si no hay bash) es la forma de «entrar» a mirar qué pasa dentro. El contenedor debe estar en marcha.

7Dockerfile

Un Dockerfile es la receta para construir tu propia imagen, instrucción a instrucción.

FROMimagen base de la que se parte
WORKDIRcarpeta de trabajo dentro de la imagen
COPYcopiar ficheros del proyecto a la imagen
RUNejecutar una orden al construir (instalar cosas)
ENVvariable de entorno
EXPOSEdocumentar el puerto que usa
CMDorden por defecto al arrancar el contenedor
ENTRYPOINTejecutable fijo del contenedor

Copia primero package.json e instala, y luego el resto del código: así Docker reutiliza la capa de dependencias mientras no cambien, y reconstruye mucho más rápido.

8Construir imágenes

El . final es el «contexto»: la carpeta que se envía a Docker para construir. Un .dockerignore evita copiar lo que no hace falta y acelera la construcción.

9Volúmenes y datos

Lo que se escribe dentro de un contenedor se pierde al borrarlo. Para conservar datos hay dos formas:

Volumengestionado por Docker: -v nombre:/ruta. Para datos (bases de datos)
Bind mountuna carpeta tuya: -v /ruta/host:/ruta. Para desarrollo

10Redes y puertos

Los contenedores de una misma red se ven entre sí por su nombre: web puede conectar a db usando db como nombre de host, sin saber su IP.

Para exponer un servicio fuera del anfitrión, publícalo con -p. Para que dos contenedores hablen entre ellos, basta con ponerlos en la misma red. Repaso de puertos en TCP/IP.

11Docker Compose

Compose define varios contenedores en un fichero compose.yaml y los levanta juntos con una orden. Ideal para una app con su base de datos.

Compose usa YAML: cuidado con la indentación (siempre espacios). Cada servicio es un contenedor con su configuración.

12Limpieza y buenas prácticas

Imágenes pequeñasparte de bases -alpine o -slim
Una cosa por contenedorun proceso por contenedor, no varios servicios juntos
No como rootcrea un usuario en el Dockerfile (USER)
No secretos en la imagenpásalos por variables o volúmenes, nunca en el Dockerfile
Aprovecha la cachéordena el Dockerfile de lo que menos cambia a lo que más

Cuidado: docker system prune -a borra todas las imágenes que no tengan un contenedor en marcha. Muy útil para liberar espacio, pero asegúrate de que no borras algo que tardaste en construir.
