La idea

VirtualBox es un hipervisor de tipo 2: corre como un programa dentro de tu sistema y crea máquinas virtuales completas. Gratuito, multiplataforma y el más usado para aprender y montar laboratorios.

Conceptos

Anfitrióntu equipo real
Invitado (guest)el sistema que corre en la VM
Tecla Hostlibera el ratón/teclado (por defecto Ctrl derecho)

1Qué es VirtualBox

Un software de virtualización que permite ejecutar varios sistemas operativos a la vez en un mismo equipo, cada uno en su máquina virtual aislada. Ideal para probar distribuciones, montar laboratorios de pentest o tener un entorno separado.

MultiplataformaWindows, macOS, Linux como anfitrión
Gratuitolibre; el Extension Pack añade USB 2/3 y más
AlternativasVMware, Hyper-V, KVM (ver Fundamentos)
Automatizablecon Vagrant o el comando VBoxManage

2Crear una máquina

El asistente Nueva pide los datos básicos. Los que importan:

Nombre y tiposi lo llamas «Ubuntu» detecta el tipo y versión solos
Memoria (RAM)2–4 GB para un escritorio; nunca pases de la mitad de tu RAM
CPUs1–2 núcleos; no asignes todos los del anfitrión
Discocrear uno virtual nuevo (sección 3)
EFIactivar si el sistema invitado lo requiere

No sobreasignes: la RAM y las CPU que das a las VM se las quitas al anfitrión. Si repartes de más, todo va lento. Deja siempre margen para tu sistema real.

3Discos virtuales

El disco de la VM es un fichero en tu equipo. Al crearlo eliges formato y tipo de reserva:

VDIformato propio de VirtualBox (el habitual)
VMDK / VHDformatos de VMware / Hyper-V, por compatibilidad
Reservado dinámicocrece según se usa; ocupa poco al principio
Tamaño fijoreserva todo el espacio ya; algo más rápido
Tamaño máximoel límite hasta el que podrá crecer (p. ej. 25 GB)

Para casi todo, VDI dinámico: pones un máximo generoso y solo ocupa lo que de verdad usa el invitado. Se pueden añadir más discos después desde la Configuración › Almacenamiento.

4Instalar el sistema

La VM arranca vacía: hay que darle la ISO del sistema como si fuera un DVD.

Almacenamiento › ópticomontar el fichero .iso en la unidad virtual
Arrancarla VM inicia desde la ISO y lanza el instalador
Orden de arranqueen Sistema; poner óptico antes que disco para instalar
Quitar la ISOtras instalar, desmóntala para arrancar del disco

Muchas distros ofrecen una imagen ya preparada para VirtualBox (.ova): en ese caso no instalas, solo la importas (sección 8).

5Guest Additions

Los Guest Additions son controladores que se instalan dentro del invitado y mejoran mucho la integración.

Pantallaresolución ajustable y modo pantalla completa
Ratónintegración fluida (sin «capturar» el puntero)
Portapapelescopiar y pegar entre anfitrión e invitado
Carpetas compartidasnecesarias para que funcionen (sección 8)
Instalarmenú Dispositivos › Insertar imagen de Guest Additions

Sin los Guest Additions la VM funciona, pero incómoda: resolución fija, ratón capturado y sin copiar-pegar. Instálalos casi siempre.

6Modos de red

El modo de red decide cómo se conecta la VM. Es lo que más se configura, sobre todo para laboratorios.

NATpor defecto; la VM sale a internet, pero no es accesible desde fuera. Aislada y cómoda
Red NATcomo NAT pero varias VM se ven entre sí y comparten salida
Adaptador puente (bridged)la VM es un equipo más de tu red física, con su IP del router
Solo anfitrión (host-only)red privada entre el anfitrión y las VM; sin internet
Red internasolo entre VM, ni siquiera el anfitrión; laboratorio aislado
Quiero internet y nada másNAT
Varias VM que se comuniquen y con internetRed NAT
Que otros equipos vean la VMPuente
Laboratorio aislado de pentestRed interna (o host-only)

Con NAT puedes redirigir puertos (Configuración › Red › Avanzado › Reenvío de puertos) para llegar a un servicio de la VM, por ejemplo el 2222 del anfitrión al 22 (SSH) del invitado.

7Snapshots

Un snapshot guarda el estado exacto de la VM en un momento; puedes volver a él cuando quieras. Imprescindible para probar sin miedo.

Tomar snapshotguarda disco (y opcionalmente memoria) en ese instante
Restaurarvuelve al estado guardado, descartando lo posterior
Árbolpuedes tener varios y ramificar desde cualquiera
Uso típicosnapshot «limpio» antes de trastear; si algo rompe, restauras

Los snapshots crecen y consumen disco: no acumules decenas. Para conservar una VM a largo plazo, mejor exportarla (sección 8) que dejar una cadena enorme de snapshots.
