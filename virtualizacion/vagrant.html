La idea

Vagrant automatiza la creación de máquinas virtuales: describes el entorno en un Vagrantfile y con vagrant up tienes una VM idéntica cada vez. Acaba con el «funciona en mi máquina» a nivel de sistema completo.

Lo mínimo

1Qué es Vagrant

Una herramienta (de HashiCorp) para construir y gestionar entornos de máquinas virtuales de forma automática y reproducible. Se apoya en un proveedor (VirtualBox, VMware, Hyper-V) que crea la VM real.

Reproducibleel mismo Vagrantfile da la misma VM en cualquier equipo
Versionableel Vagrantfile va en el repositorio, junto al código
Desechablerompes algo, destroy y vuelves a empezar limpio

Muy usado para montar laboratorios (por ejemplo, de pentesting) y entornos de desarrollo idénticos a producción.

2Vagrant o Docker

Vagrantmáquinas virtuales completas (con su propio núcleo)
Dockercontenedores que comparten el núcleo del anfitrión
Pesouna VM es pesada (GB); un contenedor, ligero (MB)
Aislamientola VM aísla más (SO entero); el contenedor, menos
CuándoVagrant: probar sistemas enteros y kernels; Docker: empaquetar apps

No compiten tanto como parece: Vagrant simula máquinas completas; Docker empaqueta aplicaciones. A veces se usan juntos.

3Instalación

Vagrant necesita un proveedor instalado. El más común y gratuito es VirtualBox. Cada proyecto vive en su carpeta, con su Vagrantfile.

4El Vagrantfile

El fichero (en Ruby) que describe la máquina. Se genera con vagrant init y se edita a mano.

5Comandos

upla primera vez descarga la box y la crea
reload --provisionreinicia y vuelve a aprovisionar
suspend / resumepausar y reanudar (guarda el estado)

6Boxes

Una box es la imagen base de la VM (un sistema ya instalado). Se descargan del catálogo público Vagrant Cloud.

Ejemplos de boxes: debian/bookworm64, ubuntu/jammy64, generic/alma9. Se buscan en Vagrant Cloud.

7Red y carpetas

Carpeta sincronizada/vagrant en la VM es tu carpeta del proyecto
private_networkred interna con IP fija, aislada
forwarded_portredirige un puerto de la VM a tu equipo
public_networkla VM en tu red real (con cuidado)

Para un laboratorio de seguridad, usa private_network y no public_network: mantén las máquinas aisladas de tu red real.

8Aprovisionamiento

El provisioning instala y configura software automáticamente al crear la VM, para que salga lista para usar.

shellejecutar comandos o un script (lo más simple)
filecopiar ficheros a la VM
ansible / puppetgestión de configuración avanzada

Se ejecuta solo la primera vez (o con vagrant provision). Combínalo con shell scripts para dejar el entorno a punto.

9Consejos

Versiona el Vagrantfileque el equipo levante el mismo entorno
No versiones .vagrant/es estado local; al .gitignore
destroy sin miedosi algo se rompe, recrea desde cero
Recursosajusta memoria y CPU; una VM consume mucho más que un contenedor
