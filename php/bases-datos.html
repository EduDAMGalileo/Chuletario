1PDO o mysqli

PDOla misma forma de trabajar con MySQL, MariaDB, PostgreSQL, SQLite, SQL Server... Orientado a objetos. Parámetros con nombre. La recomendada
mysqlisolo MySQL y MariaDB. Tiene versión de funciones y de objetos. Aparece mucho en código antiguo
mysql_*eliminada en PHP 7. Si ves mysql_query, el código es muy antiguo

PDO necesita el driver de cada base de datos activado en php.ini: extension=pdo_mysql, pdo_pgsql o pdo_sqlite. Para ver cuáles hay:

El lenguaje SQL está en SQL. Aquí se ve cómo lanzarlo desde PHP.

2Conectar

Un objeto PDO es una conexión. Se crea con un DSN (qué base de datos y dónde), usuario, contraseña y opciones.

MySQL / MariaDBmysql:host=localhost;dbname=tienda;charset=utf8mb4
PostgreSQLpgsql:host=localhost;port=5432;dbname=tienda
SQLitesqlite:/ruta/datos.db o sqlite::memory: (sin usuario ni clave)
SQL Serversqlsrv:Server=localhost;Database=tienda
ATTR_ERRMODEERRMODE_EXCEPTION: lanza PDOException (por defecto desde PHP 8)
ATTR_DEFAULT_FETCH_MODEcómo se devuelven las filas si no se indica (sección 6)
ATTR_EMULATE_PREPARESfalse: el servidor recibe la consulta y los datos por separado; los números vuelven como números
ATTR_PERSISTENTtrue: reutiliza conexiones entre peticiones

Pon siempre charset=utf8mb4 en el DSN de MySQL: sin él, las tildes y los emojis se guardan mal. utf8 a secas en MySQL solo admite 3 bytes por carácter.

3Un fichero de conexión

La conexión se escribe una vez y se incluye donde haga falta. Los datos de acceso, fuera de la carpeta pública y fuera del control de versiones.

Crea un usuario de base de datos solo para la aplicación, con los permisos justos (SELECT, INSERT, UPDATE, DELETE sobre su base de datos). Nunca root. Ver SQL: DCL.

4Consultas sin parámetros

Si la consulta no lleva ningún dato de fuera, se puede lanzar directamente.

$pdo->query($sql)ejecuta y devuelve un PDOStatement (para SELECT)
$pdo->exec($sql)ejecuta y devuelve el número de filas afectadas
$pdo->prepare($sql)prepara una consulta con huecos (sección 5)

En cuanto haya una variable en el SQL (un dato de un formulario, de la URL, de la sesión...), query y exec están prohibidos: usa prepare.

5Consultas preparadas

El SQL se envía con huecos y los datos van aparte. La base de datos nunca confunde un dato con una orden, así que no hay inyección SQL posible.

execute([...])rellena los huecos (todos como texto) y ejecuta
bindValue(hueco, valor, tipo)asigna un valor con su tipo: PDO::PARAM_INT, PARAM_STR, PARAM_BOOL, PARAM_NULL
bindParam(hueco, $var)enlaza una variable: se lee su valor al hacer execute
?se numeran desde 1 en bindValue(1, ...)

Los huecos son solo para valores. No sirven para nombres de tablas o columnas, ni para ASC/DESC. Si el usuario elige por qué columna ordenar, compruébalo contra una lista blanca: in_array($orden, ['nombre', 'precio'], true).

6Recoger los resultados

PDO::FETCH_ASSOCarray con los nombres de columna: $f['nombre']
PDO::FETCH_NUMarray por posición: $f[0]
PDO::FETCH_BOTHlas dos cosas (por defecto si no se configura)
PDO::FETCH_OBJobjeto genérico: $f->nombre
PDO::FETCH_CLASSobjeto de tu clase; rellena las propiedades con el mismo nombre que las columnas
PDO::FETCH_COLUMNsolo una columna
PDO::FETCH_KEY_PAIRprimera columna como clave, segunda como valor
fetch()la siguiente fila, o false si no quedan
fetchAll()todas las filas; array vacío si no hay
fetchColumn(n)la columna n (por defecto 0) de la siguiente fila
fetchObject(Clase)la siguiente fila como objeto
rowCount()filas afectadas por un INSERT/UPDATE/DELETE (no fiable con SELECT)
columnCount()número de columnas del resultado

7Insertar, modificar y borrar

En MySQL, rowCount() cuenta las filas que cambiaron: un UPDATE que pone el mismo valor que ya había da 0. En PostgreSQL no existe lastInsertId() sin secuencia: se usa INSERT ... RETURNING id y fetchColumn().

8Inyección SQL

Pasa cuando un dato de fuera se pega dentro del SQL: el atacante escribe un trozo de SQL en vez de un dato y cambia la consulta.

Valores (texto, números, fechas)siempre con ? o :nombre
Nombres de columnas o tablas, ASC/DESClista blanca de valores permitidos
addslashes, $pdo->quote()no los uses en lugar de las preparadas
Mensajes de errorno muestres $e->getMessage() al usuario: da pistas sobre la base de datos

Cómo se explota y cómo se detecta, en Inyección SQL y sqlmap.

10Transacciones

Varias operaciones que tienen que hacerse todas o ninguna: si falla una, se deshacen las anteriores. Teoría en SQL: TCL.

beginTransaction()desactiva el guardado automático hasta el commit
commit()confirma todos los cambios
rollBack()los deshace
inTransaction()si hay una transacción abierta

En MySQL las transacciones solo funcionan con tablas InnoDB (el motor por defecto). Las sentencias CREATE, ALTER y DROP hacen commit automático.

13Contraseñas y login

Las contraseñas no se guardan nunca en claro, ni con md5 o sha1. Se guarda un hash lento con sal, y al entrar se compara.

password_hash($clave, PASSWORD_DEFAULT)genera el hash con una sal aleatoria; cada vez sale distinto
password_verify($clave, $hash)comprueba una contraseña contra su hash
password_needs_rehash($hash, ...)si conviene recalcularlo con un algoritmo o coste más nuevo
PASSWORD_ARGON2IDalgoritmo alternativo, si el PHP lo tiene

Sesiones en Cookies y sesiones. Por qué hay que usar hash lentos en Criptografía y Fuerza bruta.
