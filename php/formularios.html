POST no es seguro por sí mismo: los datos no se ven en la URL, pero viajan en claro si no hay HTTPS, y cualquiera puede verlos y cambiarlos con las herramientas del navegador. Lo que protege es HTTPS y validar en el servidor.

3Leer los datos en PHP

$_GETparámetros de la URL (aunque la petición sea POST)
$_POSTcampos de un formulario enviado por POST
$_FILESficheros subidos
$_REQUESTmezcla de GET, POST y cookies: mejor no usarlo, no sabes de dónde viene cada dato
$_SERVER['REQUEST_METHOD']"GET", "POST"...
$_SERVER['QUERY_STRING']la parte de la URL tras el ?, sin decodificar
file_get_contents('php://input')el cuerpo en bruto, por ejemplo un JSON: json_decode(..., true)

Todo llega como string (o como array, con name="x[]"). Un type="number" llega como "20", y un campo que no se rellenó llega como "". Convierte y valida siempre.

5Formulario que se procesa a sí mismo

Lo más habitual: un solo fichero que muestra el formulario y, cuando se envía, lo procesa. Así se pueden volver a mostrar los errores y los datos que escribió el usuario.

Si quieres poner action, no uses $_SERVER['PHP_SELF'] tal cual: se puede manipular desde la URL. Déjalo vacío o escribe el nombre del fichero.

6Validar los datos

El navegador valida por comodidad; el servidor valida por seguridad. Cualquiera puede enviar una petición sin pasar por tu formulario.

FILTER_VALIDATE_INTentero; opciones min_range y max_range
FILTER_VALIDATE_FLOATdecimal (con punto)
FILTER_VALIDATE_EMAILformato de correo
FILTER_VALIDATE_URLURL completa con esquema
FILTER_VALIDATE_BOOLEANtrue para "1", "true", "on", "yes"
FILTER_VALIDATE_REGEXPcon la opción regexp
FILTER_NULL_ON_FAILUREflag: devuelve null en vez de false al fallar

Valida al recibir (¿es lo que espero?) y escapa al mostrar (sección 8) o al guardar en la base de datos (con consultas preparadas). No "limpies" los datos quitando caracteres: guárdalos tal cual y escápalos según donde vayan.

7Mostrar errores y recordar valores

Si hay errores, se vuelve a pintar el formulario con lo que el usuario escribió, para que no tenga que empezar de cero, y con cada error junto a su campo.

novalidate desactiva la validación del navegador: útil mientras pruebas que la de PHP funciona. Los campos password no se suelen rellenar de nuevo.

8Escapar la salida: XSS

Si muestras en la página algo que escribió el usuario sin escaparlo, puede meter HTML y JavaScript que se ejecutará en el navegador de quien lo vea: es un ataque XSS (cross-site scripting).

Dentro de HTML o de un atributohtmlspecialchars($x): cambia < > & " ' por entidades
Como parámetro de una URLurlencode($x) (y htmlspecialchars encima si va en un atributo)
Dentro de JavaScriptjson_encode($x)
En una consulta SQLnada de escapar a mano: consultas preparadas
Quitar etiquetasstrip_tags($x): no sustituye a escapar

Regla: todo lo que venga de fuera (formularios, URL, cookies, base de datos) se escapa al mostrarlo. Desde PHP 8.1, htmlspecialchars ya escapa las comillas simples y usa UTF-8 por defecto.

9Post/Redirect/Get

Si después de un POST se muestra la página directamente, al pulsar F5 el navegador vuelve a enviar el formulario: un pedido doble, un mensaje duplicado. La solución es redirigir tras procesar.

header() antes de cualquier salida: si ya se ha escrito algo (un echo, HTML, incluso un espacio antes de <?php), da el error headers already sent. Sesiones en Cookies y sesiones.

10Subir ficheros

['name']nombre original en el equipo del usuario (no fiable)
['type']tipo MIME que dice el navegador (no fiable)
['tmp_name']ruta temporal en el servidor; se borra al acabar el script
['size']tamaño en bytes
['error']UPLOAD_ERR_OK (0), UPLOAD_ERR_INI_SIZE (1, demasiado grande), UPLOAD_ERR_NO_FILE (4, no se eligió)...
move_uploaded_file(tmp, dest)mueve el temporal a su sitio definitivo
upload_max_filesize post_max_sizelímites en php.ini (por defecto 2 MB y 8 MB)

Con name="adjuntos[]" multiple, $_FILES['adjuntos']['name'] es un array, igual que ['tmp_name'], ['error']... Se recorren con el mismo índice: foreach ($_FILES['adjuntos']['tmp_name'] as $i => $tmp).

Nunca guardes las subidas en una carpeta donde se ejecute PHP con el nombre original: alguien puede subir shell.php y ejecutarlo. Ver Shells.

11Enlaces con parámetros

Un enlace también hace una petición GET: es la forma de pasar datos sin formulario (ver un producto, cambiar de página, ordenar).

urlencode($x)codifica un valor para la URL (espacio → +)
rawurlencode($x)igual, con espacio → %20 (para rutas)
http_build_query($array)monta a=1&b=2 codificando cada valor
parse_str($qs, $array)al revés: de query string a array

No uses GET para borrar: un enlace borrar.php?id=7 lo puede activar un buscador al rastrear o una imagen en otra web. Las acciones que cambian datos van por POST, con un botón dentro de un formulario.

12Protección CSRF

En un ataque CSRF (cross-site request forgery), otra web envía un formulario a la tuya aprovechando que el usuario ya ha iniciado sesión. Se evita con un token secreto que solo tu formulario conoce.

hash_equals compara en tiempo constante: no deja adivinar el token midiendo cuánto tarda la comparación. Las cookies de sesión con SameSite=Lax también ayudan (ver Cookies y sesiones).
