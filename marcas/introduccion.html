La idea

XML (eXtensible Markup Language) es un formato de texto para estructurar datos con etiquetas que tú defines. No «hace» nada por sí mismo: describe información para que las máquinas la intercambien y validen.

Marcas, como HTML

Como HTML, usa etiquetas <asi>. La diferencia: en HTML las etiquetas están fijadas y sirven para mostrar páginas; en XML te las inventas para describir cualquier tipo de dato.

1Qué es XML

Un metalenguaje de marcas: un conjunto de reglas para crear tus propios lenguajes de etiquetas. Es texto plano, legible por personas y máquinas, e independiente de la plataforma.

Extensibledefines tus propias etiquetas, no hay un juego fijo
Estructuradolos datos se anidan en forma de árbol
Autodescriptivolas etiquetas explican qué es cada dato
Portabletexto plano: cualquier sistema lo lee

De XML derivan formatos que usas a diario: XHTML, SVG (imágenes), RSS (noticias), los .docx/.xlsx de Office o los ficheros de configuración de muchos programas.

2Anatomía de un documento

Prólogola línea <?xml ... ?>: versión y codificación
Elementouna etiqueta de apertura y cierre: <titulo>...</titulo>
Elemento raízel que envuelve a todos (<catalogo>)
Atributodato dentro de la etiqueta: id="1"
Contenidoel texto o los elementos hijos
Vacío<salto/> se cierra en sí mismo

3Documento bien formado

Un XML está bien formado si respeta las reglas de sintaxis. Son estrictas (más que HTML):

Una sola raíztodo cuelga de un único elemento
Todo se cierracada etiqueta abierta se cierra (o es vacía />)
Bien anidadose cierran en orden inverso al que se abrieron
Distingue mayúsculas<Libro> ≠ <libro>
Atributos entre comillasid="1", nunca id=1
Caracteres especiales&lt; &gt; &amp; para < > &

Si un XML no está bien formado, el analizador (parser) lo rechaza entero: no es tolerante como los navegadores con el HTML. Un & suelto o una etiqueta sin cerrar y falla todo.

4Bien formado o válido

Dos niveles distintos de corrección que conviene no confundir:

Bien formadocumple la sintaxis de XML (sección 3). Obligatorio siempre
Válidoademás, respeta una estructura definida en un esquema (qué elementos, en qué orden, de qué tipo)

La estructura permitida se define con una gramática: una DTD o, mejor, un XML Schema. Validar comprueba que el documento encaja en ella. Un XML puede estar bien formado pero no ser válido (le falta un elemento obligatorio, por ejemplo).

5Espacios de nombres

Los namespaces evitan choques de nombres cuando se mezclan vocabularios: si dos esquemas usan <titulo> con sentidos distintos, un prefijo los distingue.

xmlnsdeclara un espacio de nombres
URIidentifica el vocabulario (no es una web que se visite)
Prefijolib: abrevia el namespace en cada etiqueta

Los verás por todas partes en XSD, SVG o los ficheros de Office. El URI es solo un identificador único; no hace falta que apunte a nada real.

6La familia XML

XML es el centro de un ecosistema de tecnologías, cada una con su papel. Este es el mapa:

DTDdefinir la estructura permitida (la gramática clásica)
XML Schema (XSD)definir la estructura con tipos de datos; sucesor de la DTD
XPathnavegar y seleccionar partes del documento por rutas
XQueryconsultar y generar XML (el «SQL del XML»)
XSLTtransformar un XML en otro formato (HTML, texto, otro XML)
XSL-FOdar formato para impresión y PDF
XLink / XPointerenlaces entre documentos y a partes concretas
DOM / SAXlas dos formas de leer XML desde un programa (en árbol o al vuelo)

XPath es transversal: lo usan XQuery, XSLT y también otras herramientas para exprimir su salida XML. Aprenderlo rinde en muchos sitios.

7Validar

Definir qué es un documento «correcto» para tu caso y comprobarlo. Dos tecnologías:

DTDsencilla y veterana; sin tipos de datos ni namespaces
XML Schemapotente: tipos (número, fecha), restricciones, namespaces. El estándar hoy
RELAX NGalternativa más simple a XSD, menos extendida

Para algo serio, XML Schema; la DTD se ve sobre todo por herencia y en documentos antiguos. Ambas definen qué elementos y atributos son válidos y en qué orden.

8Consultar y transformar

Una vez tienes el XML, quieres sacar datos de él o convertirlo en otra cosa:

XPathseleccionar nodos: «todos los títulos», «el libro con id=1»
XQueryconsultas completas con FLWOR, agrupar, construir XML nuevo
XSLTtransformar: de XML a HTML para mostrarlo en web, por ejemplo

Símil con bases de datos: XPath es como señalar celdas, XQuery es el SQL del XML, y XSLT es la plantilla que da forma al resultado.

9XML, JSON o YAML

XML ya no es la única opción para estructurar datos. Cuándo encaja cada uno:

XMLdocumentos complejos, validación estricta, formatos veteranos (Office, SVG)
JSONAPIs y web: ligero, directo, nativo en JavaScript
YAMLconfiguración legible por personas (Docker, CI/CD)

Para intercambio de datos en la web ha ganado JSON, más simple. XML sigue reinando donde importan la validación potente, los namespaces y los documentos con estructura rica.

10Dónde se usa

Documentos de oficina.docx, .xlsx, .odt son XML comprimido
GráficosSVG es XML para imágenes vectoriales
Web y noticiasRSS y Atom, XHTML, sitemaps
ConfiguraciónMaven (pom.xml), Android, muchos servidores Java

Empieza por definir la estructura con DTD o XML Schema, y luego consulta y transforma con XPath y XQuery.
