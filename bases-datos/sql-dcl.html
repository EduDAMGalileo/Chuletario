Qué controla

El DCL gestiona los permisos: qué usuario puede leer, escribir o administrar cada base, tabla o columna. Es la seguridad dentro del gestor.

Las órdenes

GRANTconceder privilegios
REVOKEretirarlos

1Qué es DCL

El Data Control Language controla el acceso a los datos. Aplica el principio de mínimo privilegio: cada cuenta debe tener solo los permisos que necesita, ni más.

Distinto de los usuarios del sistema: estos son usuarios de la base de datos, con sus propios permisos sobre tablas y bases.

2Usuarios

'dam'@'localhost'usuario + desde dónde conecta (host)
'dam'@'%'desde cualquier host
IDENTIFIED BYfija la contraseña

En MySQL un usuario es la pareja nombre + host: 'dam'@'localhost' y 'dam'@'%' son cuentas distintas. Cómo se guardan las contraseñas, en Criptografía.

3GRANT

SELECT, INSERT, UPDATE, DELETEpermisos de datos habituales
CREATE, ALTER, DROPpermisos de estructura (DDL)
ALL PRIVILEGEStodos
ON base.*toda la base; ON base.tabla una tabla
WITH GRANT OPTIONademás, poder conceder esos permisos a otros

Concede lo justo. Dar ALL PRIVILEGES «para que funcione» es el error típico que convierte una inyección SQL en un desastre total (ver sqlmap).

4REVOKE y ver permisos

REVOKE es el espejo de GRANT: mismos permisos, quitados. SHOW GRANTS lista lo que tiene una cuenta.

5Roles

Un rol es un conjunto de permisos con nombre. En vez de dárselos uno a uno a cada usuario, se los das al rol y asignas el rol a quien corresponda.

Los roles simplifican la administración cuando hay muchos usuarios con el mismo perfil (lectores, editores, administradores). Disponibles en MySQL 8+, PostgreSQL, Oracle y SQL Server.
