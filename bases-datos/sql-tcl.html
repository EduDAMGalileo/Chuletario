La idea

Una transacción agrupa varias operaciones para que ocurran todas o ninguna. El ejemplo clásico: una transferencia resta de una cuenta y suma en otra; si falla a medias, no puede quedarse el dinero en el aire.

Las órdenes

START TRANSACTIONabrir (también BEGIN)
COMMITconfirmar los cambios
ROLLBACKdeshacerlos
SAVEPOINTpunto intermedio

1Qué es una transacción

Un bloque de operaciones DML que se tratan como una unidad. Mientras la transacción está abierta, los cambios son provisionales; solo se hacen definitivos al confirmar (COMMIT).

Solo la DML (INSERT/UPDATE/DELETE) es transaccional. En muchos gestores la DDL (CREATE/ALTER/DROP) confirma sola y no se puede deshacer con ROLLBACK.

2COMMIT y ROLLBACK

COMMITconfirma: los cambios pasan a ser permanentes y visibles
ROLLBACKcancela: deshace todo lo hecho desde el inicio
Error a mediassi algo falla, se hace ROLLBACK para no dejar datos a medias

Patrón habitual en código: abrir transacción, ejecutar las operaciones dentro de un try, hacer COMMIT si todo va bien y ROLLBACK en el catch.

3SAVEPOINT

Un punto de guardado dentro de una transacción: permite deshacer parte de ella sin cancelarla entera.

ROLLBACK TO sp1 vuelve a ese punto sin cerrar la transacción; el COMMIT final confirma lo que quede. Útil en procesos largos por pasos.

4ACID

Las cuatro garantías que ofrece una transacción en una base relacional:

Atomicidadtodo o nada; si algo falla, se deshace entero
Consistenciapasa de un estado válido a otro válido (respeta las restricciones)
Aislamientolas transacciones simultáneas no se interfieren
Durabilidaduna vez confirmado, no se pierde aunque se caiga el sistema

Es lo que hace fiable a una base relacional para datos críticos (banca, pedidos). Muchas NoSQL relajan ACID a cambio de escala.

5Niveles de aislamiento

Cuánto se aíslan entre sí las transacciones simultáneas. Más aislamiento evita más problemas, pero reduce la concurrencia.

READ UNCOMMITTEDel más bajo; puede leer cambios sin confirmar (dirty read)
READ COMMITTEDsolo lee lo confirmado (por defecto en PostgreSQL)
REPEATABLE READla misma lectura da igual dos veces (por defecto en MySQL/InnoDB)
SERIALIZABLEel más alto; como si fueran en fila, una tras otra

Problemas que resuelven, de menor a mayor aislamiento: dirty read (leer sin confirmar), non-repeatable read (leer distinto dos veces) y phantom read (aparecen filas nuevas). Para la mayoría de apps, el nivel por defecto vale.

6Autocommit

Por defecto, muchos gestores confirman cada orden al instante (autocommit): cada INSERT o UPDATE es su propia transacción. Al abrir una con START TRANSACTION, se suspende hasta el COMMIT.

Cuidado con el autocommit al hacer pruebas: sin transacción explícita, un UPDATE sin WHERE se confirma solo y no hay ROLLBACK que valga. Abre una transacción cuando toques datos importantes.
