La idea

Una base de datos guarda información de forma organizada para poder consultarla, modificarla y protegerla sin perderla. En vez de leer y escribir ficheros a mano, hablas con un programa (el gestor) que se encarga de todo.

Base de datos vs gestor

Base de datosel conjunto de datos organizados
SGBD (DBMS)el programa que la gestiona: MySQL, PostgreSQL, MongoDB...

1Qué es una base de datos

Es una colección de datos organizada para que muchas aplicaciones y personas la usen a la vez, sin duplicarla ni corromperla. El gestor (SGBD) es quien la administra: guarda, busca, controla los accesos y garantiza que los datos queden bien aunque falle la luz.

Persistencialos datos siguen ahí cuando apagas el programa
Concurrenciamuchos usuarios a la vez sin pisarse
Integridadreglas que impiden datos incoherentes
Consultaspreguntar por los datos de mil maneras distintas
Seguridadquién puede ver o cambiar qué

¿Por qué no un simple fichero? Con dos usuarios a la vez, millones de filas o la necesidad de no perder nada, un fichero se queda corto enseguida. Para eso está el gestor.

2El modelo relacional

El modelo dominante desde hace décadas. Los datos se guardan en tablas (filas y columnas) que se relacionan entre sí. Es la base de MySQL, PostgreSQL, Oracle, SQL Server...

Tablaun conjunto de datos del mismo tipo (p. ej. clientes)
Fila (registro)un elemento: un cliente concreto
Columna (campo)un dato de cada fila: nombre, email...
Clave primariaidentifica cada fila de forma única (un id)
Clave foráneaapunta a la clave de otra tabla y las relaciona
Esquemala estructura definida de antemano (qué tablas y columnas hay)

La gracia es no repetir datos: en vez de copiar el cliente en cada pedido, el pedido guarda el id del cliente. Esto se llama normalizar y las tablas se recomponen con JOIN.

3SQL: el lenguaje

SQL (Structured Query Language) es el lenguaje estándar para hablar con las bases relacionales. Se organiza en familias de instrucciones:

DDLdefinir la estructura: CREATE, ALTER, DROP
DMLmanejar datos: INSERT, UPDATE, DELETE
DQLconsultar: SELECT
DCLpermisos: GRANT, REVOKE
TCLtransacciones: COMMIT, ROLLBACK

El estándar SQL es común, pero cada gestor añade lo suyo: por eso hay chuletas separadas de SQL (con sintaxis MySQL) y de PostgreSQL.

4Relacional o NoSQL

«NoSQL» agrupa las bases que no siguen el modelo relacional de tablas. No son mejores ni peores: resuelven otros problemas.

Relacional (SQL)esquema fijo, datos muy relacionados, consultas complejas, máxima consistencia
NoSQLesquema flexible, muchísimos datos, escalado horizontal, velocidad
Elige SQL si...los datos tienen estructura clara y relaciones (banca, facturas, inventario)
Elige NoSQL si...el formato varía, priorizas escala y rapidez sobre relaciones (logs, catálogos, caché)

En la práctica se combinan: una app puede usar PostgreSQL para los pedidos y Redis para la caché de sesiones. No es «o uno o el otro».

5Tipos de base de datos

El panorama completo, con un ejemplo de cada familia:

Relacionaltablas relacionadas · PostgreSQL, MySQL, Oracle, SQL Server, SQLite
Documentaldocumentos JSON flexibles · MongoDB, CouchDB
Clave-valorun valor por clave, rapidísimo · Redis, DynamoDB
Columnarorientada a columnas, para analítica masiva · Cassandra, HBase
De grafosnodos y relaciones · Neo4j (redes sociales, rutas)
De series temporalesmedidas en el tiempo · InfluxDB, TimescaleDB (sensores, métricas)

Las cuatro primeras familias NoSQL clásicas son documental, clave-valor, columnar y de grafos. Las demás son especializadas para un tipo de dato concreto.

6ACID y transacciones

Una transacción es un grupo de operaciones que deben ocurrir todas o ninguna (transferir dinero: restar de una cuenta y sumar en otra). Las bases relacionales garantizan las propiedades ACID:

Atomicidadtodo o nada; si algo falla, se deshace entero
Consistenciala base pasa de un estado válido a otro válido
Aislamientolas transacciones simultáneas no se interfieren
Durabilidaduna vez confirmado, no se pierde aunque se caiga el sistema

Muchas NoSQL relajan ACID a cambio de escala y velocidad (modelo «BASE», consistencia «eventual»): los datos se sincronizan al poco, no al instante. Bien para un «me gusta»; mal para un saldo bancario.

7Tecnologías más usadas

PostgreSQLrelacional avanzada, libre; la favorita actual. Ver chuleta
MySQL / MariaDBrelacional libre, muy extendida en la web
SQLiterelacional en un solo fichero, sin servidor; móviles y apps de escritorio
Oracle / SQL Serverrelacionales de empresa, de pago
MongoDBdocumental, la NoSQL más popular
Redisclave-valor en memoria; caché y colas
Elasticsearchbúsqueda de texto y analítica de logs

Para aprender, SQLite (cero instalación) o PostgreSQL (potente y gratis) son las mejores puertas de entrada al mundo relacional.

Catálogos flexiblesfichas con campos que cambian (documental)
Recomendaciones«amigos de amigos», rutas (grafos)
Monitorizaciónmétricas de sensores y servidores (series temporales)
