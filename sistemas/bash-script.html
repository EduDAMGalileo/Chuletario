1Variables

Comillas

"..."sustituye $var y $(orden); mantiene los espacios
'...'todo tal cual, sin sustituir nada
\escapa el carácter siguiente: \$, \"
sin comillasparte el valor por los espacios y expande *

Cuidado: nombre = "Ana" falla: Bash intenta ejecutar una orden llamada nombre. Y pon las variables entre comillas ("$fichero"): si el valor tiene espacios, sin comillas se parte en varios argumentos.

[[ ... ]]propia de Bash: admite &&, ||, patrones y expresiones regulares
(( ... ))comparaciones numéricas con < > ==

Números

Cadenas

6Bucles

breaksale del bucle
continuesalta a la siguiente vuelta
break 2sale de dos bucles anidados
seq 1 2 101 3 5 7 9: como {1..10..2} pero admite variables

Cuidado: {1..$n} no funciona, porque las llaves se expanden antes que las variables. Usa for (( i = 1; i <= n; i++ )) o $(seq 1 "$n").

9Manipular cadenas

${#s}longitud
${s:2:3}trozo: desde la posición 2, 3 caracteres
${s#patrón}quita el principio más corto que encaje; ## el más largo
${s%patrón}quita el final más corto que encaje; %% el más largo
${s/a/b}reemplaza la primera aparición; // todas
${s^^} ${s,,}a mayúsculas / minúsculas
${s:-valor}valor si s está vacía o sin definir
${s:=valor}lo mismo, y además se lo asigna
${s:?mensaje}si está vacía, muestra el error y para el script

10Funciones

$1 $2 $# $@dentro de una función son sus argumentos, no los del script
local varvariable local; sin local, es global
return 1sale con ese código (0 a 255)
function nombre { }otra forma de definirla, solo en Bash

Cuidado: return no devuelve datos, solo un código de éxito o error. Las funciones tienen que estar definidas antes de la línea que las llama.

11Códigos de salida y redirecciones

> >>salida a un fichero: sobrescribir / añadir

<<EOFtexto de varias líneas como entrada (here document)

12Depurar y despistes habituales

bash -n script.shcomprueba la sintaxis sin ejecutar
bash -x script.shmuestra cada línea con las variables ya sustituidas
set -x … set +xlo mismo, solo en un trozo del script
shellcheck script.shdetecta errores típicos (sudo apt install shellcheck)

$'\r': command not found: el script se guardó en Windows con saltos de línea CRLF. Conviértelo con dos2unix script.sh o sed -i 's/\r$//' script.sh, y en VS Code cambia «CRLF» por «LF» en la barra inferior.

sh script.sh no es lo mismo que bash script.sh: en Debian y Ubuntu, sh es dash, que no entiende [[ ]], arrays ni {1..10}, y además ignora el shebang.

cd carpeta sin comprobar: si falla, el resto del script sigue en la carpeta equivocada. Mejor cd carpeta || exit 1.
