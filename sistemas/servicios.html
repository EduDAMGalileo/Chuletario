1Qué es un demonio y systemd

Un demonio (daemon) es un programa que corre en segundo plano, sin terminal ni usuario delante: un servidor web, la base de datos, el SSH... Su nombre suele acabar en d: sshd, systemd, cupsd.

systemd es el primer proceso que arranca (PID 1) y el que gestiona todos los demás. Cada cosa que administra es una unit; las de tipo servicio terminan en .service.

.serviceun servicio (un demonio)
.socketun puerto o socket que arranca el servicio al recibir tráfico
.timerun temporizador (alternativa a cron)
.targetun grupo de units (un «modo» del sistema)

systemctl controla servicios; journalctl lee sus registros. Son las dos herramientas de esta chuleta.

2Controlar servicios

is-active nombre¿está corriendo? Responde active / inactive
is-enabled nombre¿arranca al inicio?
mask / unmaskbloquear un servicio para que no se pueda arrancar

Diferencia clave: start lo arranca ahora; enable hace que arranque en cada inicio. Casi siempre quieres las dos cosas: enable --now.

3Ver y buscar servicios

En list-unit-files, la columna enabled/disabled dice si arranca solo; en list-units, active (running) dice si está en marcha ahora mismo.

4Anatomía de un unit

Un fichero .service tiene tres secciones. Los del sistema viven en /etc/systemd/system/ (los tuyos) y /lib/systemd/system/ (los de los paquetes).

[Unit]descripción y orden de arranque (After, Requires)
[Service]qué se ejecuta y cómo
[Install]a qué target se engancha con enable

6Opciones clave del unit

ExecStart=la orden que arranca el servicio (ruta absoluta)
Type=simpleel proceso no se bifurca (lo normal)
Type=forkingel programa se va a segundo plano él solo
Type=oneshothace algo y termina (scripts de tarea única)
Restart=on-failurereiniciar si falla; también always
RestartSec=5esperar 5 s antes de reiniciar
User= · Group=con qué usuario corre (no lo dejes como root si no hace falta)
WorkingDirectory=carpeta de trabajo
Environment=variables de entorno: Environment=PORT=8080
EnvironmentFile=leer variables de un fichero
ExecReload=qué hacer en reload

Por seguridad, crea un usuario dedicado sin privilegios para tu servicio y ponlo en User=. Si el programa se ve comprometido, el daño queda acotado.

7Registros con journalctl

-u nombrefiltrar por servicio
-fseguir en tiempo real
-esaltar al final
--since · --untilrango de tiempo: "2024-01-01 10:00", "1 hour ago"
-pprioridad: err, warning, info

Si el diario ocupa mucho: journalctl --disk-usage para verlo y sudo journalctl --vacuum-time=7d para dejar solo la última semana.

8Puertos y sockets

Para saber qué servicio está escuchando en qué puerto, la herramienta moderna es ss (sustituye a netstat):

-t · -uTCP · UDP
-lsolo los que escuchan (listening)
-pmostrar el proceso (necesita sudo)
-nnúmeros de puerto en vez de nombres

ss -tulpn es la orden estrella para auditar qué expone un equipo. Lo que no debería estar abierto, se para y se deshabilita; lo demás, se filtra con el cortafuegos.

9Objetivos y arranque

Los targets son grupos de servicios que definen el estado del sistema (el equivalente moderno a los antiguos «niveles de ejecución»).

multi-user.targetsistema completo sin interfaz gráfica (servidores)
graphical.targetlo anterior más el escritorio
rescue.targetmodo mínimo de rescate

10Servicios de usuario

Puedes tener servicios propios sin ser root, que corren solo con tu sesión. Van en ~/.config/systemd/user/ y se manejan con --user.

Útil para tareas personales (un bot, una sincronización) sin tocar la configuración del sistema ni pedir permisos de administrador.

11Despistes habituales

Editar y no recargartras tocar un .service, daemon-reload siempre
start vs enableuno arranca ahora; el otro, en cada inicio. Suele hacer falta enable --now
Rutas relativasExecStart necesita la ruta absoluta del ejecutable
Correr como rootpon User= con una cuenta sin privilegios siempre que puedas
No mirar el logsi status dice «failed», journalctl -u nombre -n 50 dice por qué

Para ejecutar algo a una hora o cada cierto tiempo en vez de dejarlo siempre corriendo, usa Tareas programadas (cron o timers).
