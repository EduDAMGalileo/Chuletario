Antes de empezar

Solo con autorización. sqlmap ataca de verdad una base de datos: extrae datos, puede modificarlos y, según el motor, llegar a ejecutar órdenes en el servidor. Úsalo únicamente contra aplicaciones tuyas o creadas para practicar (DVWA, bWAPP, Juice Shop, testphp.vulnweb.com). Lanzarlo contra un sitio ajeno es un delito, aunque «solo estés probando».

La orden mínima

--batch responde solo a las preguntas con la opción por defecto: ideal para empezar sin frenarte en cada paso.

Se va de lo general a lo concreto: primero qué bases hay, luego sus tablas, después las columnas y por último el contenido.

1Qué es la inyección SQL

Ocurre cuando una aplicación mete lo que escribe el usuario dentro de una consulta SQL sin separarlo del código. El atacante «cierra» el dato y añade SQL propio.

sqlmap automatiza encontrar y aprovechar ese fallo. Entender la causa es lo que te permite luego arreglarlo (sección 11).

2Instalación y objetivo

-u "URL"la dirección con el parámetro a probar
-p idprobar solo ese parámetro
--batchno preguntar: usar la respuesta por defecto
-v 3ver las consultas que envía (niveles 0-6)
--flush-sessionempezar de cero, sin usar lo cacheado

sqlmap guarda lo que descubre en ~/.local/share/sqlmap/output/, así que la segunda vez sobre el mismo objetivo va mucho más rápido.

3Indicar la petición

-u "http://.../f.php?id=1"parámetro en la URL (GET)
--data "user=a&pass=b"datos de un formulario (POST)
--cookie "PHPSESSID=..."enviar cookies (sesión iniciada)
-r peticion.txtusar una petición HTTP guardada (p. ej. desde Burp)
--method PUTforzar el método HTTP
-p idlimitar la prueba a ese parámetro
--param-del ";"separador entre parámetros si no es &

Lo más cómodo es capturar la petición con el proxy de Burp o de ZAP, guardarla en un fichero y pasársela con -r: así respetas cabeceras, cookies y método sin escribirlos a mano.

4Enumerar la base de datos

--dbslistar las bases de datos
--current-dbla base que usa la aplicación
--current-usercon qué usuario se conecta
--is-dba¿es administrador de la base?
-D tienda --tablestablas de la base tienda
-D tienda -T usuarios --columnscolumnas de esa tabla
--schemaestructura completa de golpe
--countcuántas filas hay en cada tabla

5Volcar datos

--dumpvolcar el contenido de lo seleccionado
-D tienda -T usuarios --dumptoda una tabla
-C usuario,clave --dumpsolo esas columnas
--dump-alltodo (mucho ruido; en laboratorio)
--where "id>10"filtrar qué filas se sacan
--start 1 --stop 20limitar el número de filas

Si una columna parece una contraseña con hash, sqlmap se ofrece a probar un ataque de diccionario para descifrarla. Los resultados se guardan también en un CSV dentro de la carpeta de salida.

6Nivel y riesgo

--level 1-5cuántos sitios prueba (cabeceras, cookies...). Por defecto 1
--risk 1-3cómo de agresivas son las pruebas. Por defecto 1

Subir el nivel y el riesgo encuentra más fallos, pero manda muchas más peticiones y algunas pueden modificar datos. Sube poco a poco.

Cuidado: --risk 3 incluye consultas OR que en un UPDATE pueden afectar a todas las filas de una tabla. No lo uses sobre datos que te importe conservar.

7Autenticación y cabeceras

--cookie "..."cookies de una sesión ya iniciada
--auth-type Basicautenticación HTTP (también Digest)
--auth-cred user:passcredenciales de esa autenticación
-H "X-API-Key: abc"añadir una cabecera
--user-agent "..."cambiar el User-Agent
--random-agentUser-Agent de navegador al azar
--proxy http://127.0.0.1:8080pasar por Burp o ZAP para ver el tráfico

Para probar zonas que exigen login, inicia sesión en el navegador, copia la cookie desde las herramientas de desarrollo y pásasela con --cookie.

8Técnicas de inyección

Con --technique eliges qué métodos prueba. Cada letra es uno:

Bbooleana a ciegas: deduce por si la página cambia o no
Tpor tiempo: mide retardos que provoca la consulta
Epor mensajes de error de la base de datos
Ucon UNION: añade una consulta a la original
Sconsultas apiladas (varias separadas por ;)
Qconsultas dentro de otras (inline)

Si ya sabes el gestor, indícalo con --dbms (mysql, postgresql, mssql, oracle, sqlite): ahorra pruebas y va más rápido.

9Ir más allá del dato

Según el motor y los permisos, sqlmap puede hacer más que leer tablas:

--passwordsvolcar los hashes de las cuentas del gestor
--sql-query "SELECT ..."lanzar una consulta concreta
--sql-shelluna consola SQL interactiva
--file-read /etc/passwdleer un fichero del servidor
--os-shellintentar una shell del sistema operativo

Estas opciones son intrusivas de verdad. --os-shell y --file-read tocan el servidor, no solo la base de datos. Resérvalas para tu propio laboratorio y solo cuando el alcance autorizado lo incluya expresamente.

10Evasión y rendimiento

--threads 5más hilos: va más rápido (máximo 10)
--delay 1segundos de espera entre peticiones
--timeout 30cuánto esperar cada respuesta
--tamper space2commenttransformar la carga para sortear filtros
--list-tampersver todos los scripts de tamper

Los scripts de tamper modifican las consultas (comentarios, mayúsculas, codificación) para probar cómo responde un WAF. Sirven para auditar tus propias defensas.

Ver el tráfico real con --proxy hacia Burp enseña muchísimo: puedes leer exactamente qué consulta manda sqlmap en cada técnica.

11Cómo defenderse

La razón de entender el ataque es saber cerrarlo. La inyección SQL se evita en el código, no con un cortafuegos:

Consultas preparadasla medida principal; separa el código de los datos
Validar la entradasi esperas un número, comprueba que lo es
Mínimos privilegiosla cuenta de la web no debe ser administradora del gestor
No mostrar erroresoculta los mensajes de la base de datos en producción
WAFcapa extra, nunca un sustituto del código correcto

Más sobre PDO y consultas preparadas en la chuleta de bases de datos y de PHP.

12Normas de uso

Trabaja solo sobre aplicaciones tuyas o de laboratorio, y con permiso por escrito y alcance definido cuando audites las de otra persona. Empieza con nivel y riesgo bajos. Recuerda que --dump extrae datos reales: trátalos como información sensible y bórralos al terminar. Y no dejes --os-shell ni escuchas abiertas. El objetivo de aprender esto es construir aplicaciones que no se puedan inyectar.
