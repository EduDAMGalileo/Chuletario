Marcos de referencia

PTES, OWASP, OSSTMM y MITRE ATT&CK: qué problema resuelve cada uno, cómo se estructuran y cuándo usar cuál.

La idea de fondo

Ningún marco sustituye a los demás: cada uno responde a una pregunta distinta. PTES dice en qué orden trabajar. OWASP dice qué fallos buscar en una web. OSSTMM dice cómo medir lo que se ha cubierto. MITRE ATT&CK dice qué hacen los atacantes reales, sin imponer un orden. En la práctica se combinan.

Cómo se combinan en un pentest

Las fases del pentest siguen el orden de PTES; dentro de la fase de explotación web se usa el checklist de OWASP; al cerrar, OSSTMM ayuda a justificar qué se cubrió; y si el objetivo es imitar una amenaza concreta (ransomware, un grupo APT), se eligen técnicas del catálogo de MITRE ATT&CK.

1Por qué hay varios marcos

Un pentest necesita responder a tres preguntas distintas, y ningún documento único las cubre bien las tres a la vez:

¿En qué orden trabajo?lo responde un marco de proceso (PTES, OSSTMM)
¿Qué fallos busco aquí?lo responde una guía técnica por tipo de objetivo (OWASP para web)
¿Cómo ataca de verdad un adversario?lo responde un catálogo de comportamiento (MITRE ATT&CK)

Por eso la chuleta de Pentest ya usa PTES como columna vertebral (sus cinco fases son una simplificación de las siete de PTES) y aquí se profundiza en cada marco por separado.

2PTES: las fases de un pentest

Penetration Testing Execution Standard. Define siete fases, de la negociación del contrato al informe final, y es el marco de proceso más citado para estructurar una auditoría.

1· Pre-engagementacordar alcance, reglas y autorización por escrito
2· Intelligence gatheringreconocimiento — el mismo paso 1 de la chuleta de Pentest
3· Threat modelingqué activos importan y quién querría atacarlos
4· Vulnerability analysisescaneo y enumeración de fallos (paso 2)
5· Exploitationaprovechar los fallos para obtener acceso (paso 3)
6· Post exploitationescalar, moverse y medir el impacto real (paso 4)
7· Reportingdocumentar hallazgos y recomendaciones (paso 5)

PTES añade una fase explícita de threat modeling que la versión resumida de cinco fases da por hecha dentro del reconocimiento: pensar qué le interesa proteger al cliente antes de lanzar la primera herramienta.

3OWASP: aplicaciones web

Open Worldwide Application Security Project. No define fases de un pentest: es la referencia de qué fallos buscar en una aplicación web, con dos documentos principales.

OWASP Top 10

Las diez categorías de riesgo más comunes en apps web, revisadas cada pocos años. La edición 2021 incluye, entre otras:

A01 — Control de acceso rotoun usuario llega a datos o acciones que no le corresponden
A02 — Fallos criptográficosdatos sensibles sin cifrar o con cifrado débil
A03 — InyecciónSQL, NoSQL, comandos... — ver la chuleta de Inyección SQL
A05 — Configuración incorrectavalores por defecto, servicios innecesarios, errores visibles
A07 — Fallos de identificación y autenticaciónsesiones, contraseñas y credenciales mal gestionadas

OWASP WSTG

Web Security Testing Guide: una guía mucho más extensa y técnica, con cientos de pruebas concretas organizadas por categoría (gestión de configuración, autenticación, gestión de sesión, validación de entradas, lógica de negocio...). Donde el Top 10 dice qué buscar, el WSTG dice cómo probarlo paso a paso.

Existe también un OWASP Mobile Top 10 y un API Security Top 10, con el mismo enfoque aplicado a apps móviles y APIs.

4OSSTMM: medir la superficie

Open Source Security Testing Methodology Manual. Aporta algo que PTES y OWASP no dan: una forma de medir cuánta superficie de ataque queda expuesta tras la auditoría, no solo una lista de hallazgos.

Divide lo auditable en seis canales:

Humanoingeniería social, políticas y formación del personal
Físicoacceso a instalaciones, cerraduras, cámaras
InalámbricoWi-Fi, Bluetooth, RFID
Telecomunicacionestelefonía, PBX, módems
Redes de datoslo que cubren el resto de chuletas de este tema

Su indicador, el RAV (Risk Assessment Value), combina lo que está expuesto, los controles que hay y las pérdidas posibles en un único número comparable entre auditorías. Se usa menos que PTES u OWASP, pero es la referencia cuando el cliente pide algo medible y no solo una lista de fallos.

5MITRE ATT&CK: el mapa del adversario

No es un proceso con fases en orden: es una matriz que cataloga comportamientos reales de atacantes, observados en incidentes de verdad. Se organiza en dos niveles:

Tácticasel por qué: Reconnaissance, Initial Access, Execution, Persistence, Privilege Escalation, Defense Evasion, Credential Access, Lateral Movement, Exfiltration, Impact...
Técnicasel cómo, dentro de cada táctica: cientos, cada una con ejemplos de grupos reales que la han usado

A diferencia de PTES, las tácticas no se recorren en línea recta: un atacante real salta entre ellas, repite algunas y se salta otras según lo que encuentra.

Red teamelige técnicas concretas para imitar a un grupo o amenaza específica
Blue teammapea sus detecciones contra la matriz para ver qué huecos de cobertura tiene
ATT&CK Navigatorherramienta web para marcar y comparar técnicas sobre la matriz

Útil para ir más allá de «encontré un fallo» y hablar en los mismos términos que el resto de la industria: «esto corresponde a la técnica T1059 (Command and Scripting Interpreter)».

6Cuál usar en cada caso

Estructurar la auditoría de principio a finPTES
Auditar una aplicación o API webOWASP (Top 10 + WSTG)
Justificar con una métrica cuánto se ha cubiertoOSSTMM
Simular una amenaza real o evaluar detección (red/blue team)MITRE ATT&CK

No son excluyentes: un mismo informe puede seguir las fases de PTES, usar el checklist de OWASP durante la fase de explotación web y citar técnicas de ATT&CK en los hallazgos para dar contexto de cómo las usan atacantes reales.

7Otros marcos y normas

NIST SP 800-115guía técnica de pruebas de seguridad de la administración de EE. UU.
ISSAFInformation Systems Security Assessment Framework, precursor de PTES
CVSSno es un marco de proceso, sino la escala (0-10) para puntuar la gravedad de cada hallazgo
ISO/IEC 27001norma de gestión de la seguridad de la información; el pentest es una pieza dentro de ella

Para una auditoría de nivel estudiante o de empresa pequeña, con PTES + OWASP ya se cubre la mayoría de lo necesario; CVSS se usa casi siempre para puntuar los hallazgos en el informe.
