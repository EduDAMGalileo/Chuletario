La idea

HTTP es el protocolo con el que el navegador (cliente) pide páginas y datos a un servidor. Funciona por petición-respuesta: el cliente pregunta, el servidor contesta. Es de la capa de aplicación, sobre TCP.

Petición → Respuesta

1Qué es HTTP

HyperText Transfer Protocol: el protocolo de la World Wide Web. Define cómo se piden y se envían recursos (páginas, imágenes, datos) entre un cliente y un servidor.

Cliente-servidorel cliente pide, el servidor responde
Sin estadocada petición es independiente; no recuerda la anterior
Textuallos mensajes son texto legible (hasta HTTP/2)
Sobre TCPpuerto 80 (HTTP) y 443 (HTTPS)

Que sea «sin estado» es clave: como no recuerda nada entre peticiones, para saber quién eres se usan cookies y sesiones (sección 9).

2Petición y respuesta

Toda comunicación HTTP es un intercambio: el cliente envía una petición (request) y el servidor devuelve una respuesta (response).

Cada recurso de una web (el HTML, cada imagen, cada script) es una petición HTTP distinta. Una sola página puede lanzar decenas.

3Anatomía de una petición

Línea inicialmétodo + ruta + versión
Cabecerasmetadatos: tipo de contenido, autenticación...
Cuerpolos datos (en POST/PUT); opcional

La respuesta tiene la misma forma: línea de estado (HTTP/1.1 200 OK), cabeceras y cuerpo.

4Métodos

GETpedir un recurso (no modifica nada)
POSTenviar datos, crear un recurso
PUTcrear o reemplazar un recurso entero
PATCHmodificar parte de un recurso
DELETEborrar un recurso
HEADcomo GET pero solo las cabeceras
OPTIONSqué métodos admite el servidor

GET es seguro (no cambia nada) e idempotente (repetirlo da igual). POST no: enviar dos veces un formulario crea dos registros.

5Códigos de estado

1xxinformativo
2xxéxito: 200 OK, 201 Created, 204 No Content
3xxredirección: 301 (permanente), 302, 304 Not Modified
4xxerror del cliente: 400, 401, 403, 404 Not Found
5xxerror del servidor: 500, 502, 503
401 vs 403no autenticado (¿quién eres?) vs autenticado pero sin permiso
404 vs 500no existe el recurso vs falló el servidor

Regla mnemotécnica: 2xx bien, 3xx «mira en otro sitio», 4xx «te has equivocado tú», 5xx «me he equivocado yo (el servidor)».

7HTTPS y TLS

HTTPS es HTTP cifrado con TLS. Todo el intercambio va protegido: nadie por el medio puede leerlo ni alterarlo.

Confidencialidadel tráfico va cifrado
Integridadno se puede modificar sin que se note
Autenticidadel certificado prueba que el servidor es quien dice
Certificadolo emite una CA (autoridad de certificación); gratis con Let's Encrypt
Puerto443

El candado del navegador significa que la conexión está cifrada y el certificado es válido, no que el sitio sea «de fiar». Más sobre cifrado en la sección de Seguridad.

8Versiones

HTTP/1.1textual; una petición tras otra por conexión
HTTP/2binario; varias peticiones a la vez por una conexión (multiplexación)
HTTP/3sobre QUIC (UDP); más rápido y resistente a pérdidas

Las versiones son compatibles hacia atrás: el navegador y el servidor negocian la más alta que ambos soporten.

9Estado y cookies

Como HTTP no recuerda nada entre peticiones, para mantener una sesión (saber que ya te has identificado) se usan cookies: el servidor manda Set-Cookie y el navegador la reenvía en cada petición.

Cómo se crean y gestionan del lado del servidor, y cómo verlas en el navegador, en la chuleta de Cookies y sesiones (PHP).
