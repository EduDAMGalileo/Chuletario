Las implementaciones de Map

Map no es una Collection: no tiene add ni se recorre directamente con for-each. Se recorren sus vistas: keySet(), values() y entrySet().

1Crear y usar un Map

Cuidado: get devuelve null tanto si la clave no está como si su valor es null. Y si guardas el resultado en un int, el null provoca NullPointerException. Usa getOrDefault o containsKey.

2Métodos de Map

put(k, v)añade o sustituye; devuelve el valor anterior o null
putIfAbsent(k, v)solo si la clave no está
putAll(otro)copia todas las parejas de otro mapa
get(k)el valor, o null
getOrDefault(k, def)el valor, o def si no está
containsKey(k)¿existe la clave?
containsValue(v)¿existe el valor? (recorre todo)
remove(k)quita la pareja; devuelve el valor
remove(k, v)quita solo si tiene ese valor
replace(k, v)sustituye solo si la clave ya está
replaceAll((k, v) -> ...)recalcula todos los valores
merge(k, v, f)pone v, o combina con el que había (sección 4)
compute...(k, f)calcula el valor nuevo (sección 4)
keySet()Set con las claves
values()Collection con los valores (puede repetir)
entrySet()Set<Map.Entry<K, V>> con las parejas
size() isEmpty() clear()tamaño, vacío, vaciar
forEach((k, v) -> ...)recorrer con lambda

keySet, values y entrySet son vistas: si borras algo de ellas, se borra del mapa. notas.values().removeIf(n -> n < 5) quita a los suspensos.

3Recorrer

Cuidado: recorrer keySet() y hacer get(clave) dentro busca cada clave dos veces. Si necesitas los dos, usa entrySet().

4Actualizar sin if: merge y compute

merge(k, v, f)no está: pone v. Está: pone f(viejo, v)
computeIfAbsent(k, f)no está: pone f(k) y lo devuelve. Está: devuelve el que hay
computeIfPresent(k, f)está: pone f(k, viejo)
compute(k, f)siempre: pone f(k, viejo o null)

En los cuatro, si la función devuelve null, la clave se borra del mapa.

Cuidado: no cambies un objeto que se usa como clave de un HashMap si eso altera su hashCode: el mapa ya no lo encontrará. Las claves deberían ser inmutables (String, Integer, records, enums).

6TreeMap: navegar por claves

Útil para tramos (notas, tarifas, franjas horarias): se guarda el inicio de cada tramo como clave y floorEntry encuentra al que pertenece un valor.

7LinkedHashMap como caché LRU

LRU = Least Recently Used: cuando no cabe más, se descarta lo que hace más tiempo que no se usa. Con el constructor normal (new LinkedHashMap<>()) el orden es el de inserción.

8EnumMap y Hashtable

Cuidado: Hashtable sincroniza cada operación y no admite null ni como clave ni como valor. En código nuevo: HashMap, o ConcurrentHashMap si hay varios hilos. Properties, que lee ficheros .properties, sí sigue heredando de ella.
