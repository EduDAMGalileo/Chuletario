Genéricos

Escribir clases, interfaces y métodos que funcionan con cualquier tipo sin perder la comprobación del compilador: parámetros de tipo, límites, comodines y borrado de tipos.

Los genéricos dan seguridad de tipos (el compilador comprueba qué entra), quitan los casts y permiten reutilizar el mismo código con tipos distintos.

4Métodos genéricos

Un método genérico puede estar en una clase que no lo es. Y en una clase genérica, un método que usa la T de la clase no es un método genérico: no lleva su propio <T>.

5Límites: extends

En los genéricos, extends vale tanto para clases como para interfaces: significa «es un subtipo de».

6Comodines: ?

List<?>lista de cualquier cosa; se lee como Object, no se puede añadir (salvo null)
List<? extends Number>de Number o hijas; se lee como Number, no se puede añadir
List<? super Integer>de Integer o padres; se puede añadir Integer, se lee como Object
List<Object>no es lo mismo que List<?>: solo admite exactamente List<Object>

7? extends y ? super (PECS)

PECS: Producer Extends, Consumer Super. Si la colección te da datos (la lees), usa ? extends. Si la colección recibe datos (escribes en ella), usa ? super.

Por eso en el JDK aparecen firmas como sort(Comparator<? super T> c): un comparador de Persona sirve para ordenar una lista de Alumno.

8Borrado de tipos y restricciones

Los genéricos solo existen para el compilador. Al generar el .class, List<String> y List<Integer> quedan como List y se añaden los casts necesarios. Es el borrado de tipos (type erasure). De ahí vienen estas limitaciones:

new T()no se puede: al ejecutar no se sabe qué es T. Pasa un Supplier<T>
new T[10]no se puede; usa una List<T>
x instanceof List<String>no compila; solo instanceof List<?>
static T campono se puede: lo estático es de la clase, y T es de cada objeto
List<int>no se puede: solo tipos objeto (List<Integer>)
sobrecargaf(List<String>) y f(List<Integer>) chocan: tras el borrado son iguales
excepcionesuna clase genérica no puede extender Exception

Raw types: el tipo sin genérico

Cuidado: los raw types existen solo por compatibilidad con código anterior a Java 5. Si el compilador avisa de unchecked, falta poner el tipo entre ángulos.

10Despistes habituales

Olvidar el <> al crearnew ArrayList() es un raw type; escribe new ArrayList<>()
Esperar que List<Hija> sea List<Padre>no lo es: usa List<? extends Padre>
Añadir a una List<? extends X>no se puede: es de solo lectura
Poner <T> en el sitio equivocadoen un método va antes del tipo de retorno: static <T> void f(T x)
Usar primitivosMap<String, Integer>, no Map<String, int>
