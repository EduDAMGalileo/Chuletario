1Qué librería usar

El JDK no trae nada para JSON: siempre hace falta una librería externa. Todas hacen lo mismo con nombres distintos.

Jacksonla más usada (Spring la trae de serie). Rápida, muy configurable, con anotaciones. Usa getters y setters o constructores
Gsonde Google. Muy sencilla: trabaja directamente con los atributos, sin getters ni constructor vacío
org.jsonmínima: solo JSONObject y JSONArray, como mapas y listas. No convierte a tus clases
Jakarta JSON-P / JSON-Bel estándar de Jakarta EE (jakarta.json). Se ve en servidores de aplicaciones
Guardar y cargar mis objetosJackson ObjectMapper o Gson
Leer unos pocos campos de un JSON grande o raroárbol: JsonNode, JsonObject o JSONObject
Montar un JSON a mano, sin clasesObjectNode, JsonObject o JSONObject
Proyecto Spring BootJackson, ya incluido

2Dependencias

En el pom.xml, dentro de <dependencies>. Solo la de la librería que vayas a usar. Más sobre esto en Maven.

Jackson 3 cambia el paquete a tools.jackson.databind (grupo tools.jackson.core), trae las fechas de java.time de serie, se configura con JsonMapper.builder() y sus excepciones dejan de ser comprobadas. Las anotaciones siguen en com.fasterxml.jackson.annotation. Esta chuleta usa Jackson 2, que es lo que encontrarás en casi todos los proyectos.

3Tipos JSON y tipos Java

{ ... } objetoun objeto de tu clase, o Map<String, Object>
[ ... ] arrayList<T>, Set<T> o T[]
"texto"String, char, un enum (por su nombre), LocalDate (con soporte)
12 12.5int, long, double, BigDecimal...
true falseboolean
nullnull (en un primitivo, su valor por defecto)

El nombre de cada clave se empareja con el nombre del atributo (o del getter / setter, o del componente del record). Si no coinciden, se cambia con una anotación.

Ojo con los mapas sin tipo: al leer a Map<String, Object>, Jackson da Integer o Double según el número, pero Gson da siempre Double: 12 llega como 12.0.

4Jackson: objetos ↔ JSON

Todo pasa por un ObjectMapper. Es seguro entre hilos y costoso de crear: crea uno y reutilízalo.

writeValueAsString(obj)a un String
writeValue(destino, obj)a un File, OutputStream o Writer
writeValueAsBytes(obj)a un byte[] en UTF-8
writerWithDefaultPrettyPrinter()un escritor que pone sangría
readValue(origen, Clase.class)lee un objeto de esa clase
readValue(origen, TypeReference)lee un tipo genérico (sección 5)
readTree(origen)lee a un árbol JsonNode (sección 8)
convertValue(obj, Clase.class)convierte sin pasar por texto: de Map a objeto y al revés

Qué necesita la clase

recordfunciona tal cual (Jackson 2.12+)
Para escribirgetters públicos (getTitulo, isDisponible) o atributos públicos
Para leerconstructor sin parámetros + setters, o un constructor con @JsonCreator

Lanza JsonProcessingException (JSON mal formado o que no encaja con la clase) e IOException al usar ficheros. La primera hereda de la segunda: un catch (IOException e) recoge las dos.

5Jackson: listas, mapas y genéricos

Por el borrado de tipos, List<Libro>.class no existe. Para leer un tipo genérico se usa una TypeReference: una clase anónima que conserva el tipo completo.

Sin TypeReference: mapper.readValue(f, List.class) compila, pero dentro no hay Libro, sino LinkedHashMap. Falla después, al hacer libros.get(0).titulo(), con ClassCastException.

6Jackson: configuración y fechas

SerializationFeature.INDENT_OUTPUTescribe con sangría
SerializationFeature.WRITE_DATES_AS_TIMESTAMPSactiva: fechas como números o arrays; desactívala para tener texto ISO
SerializationFeature.FAIL_ON_EMPTY_BEANSfalla con objetos sin nada que escribir (sin getters)
DeserializationFeature.FAIL_ON_UNKNOWN_PROPERTIESactiva por defecto: una clave del JSON que no está en la clase lanza excepción
DeserializationFeature.ACCEPT_SINGLE_VALUE_AS_ARRAYacepta "x" donde se esperaba ["x"]
DeserializationFeature.FAIL_ON_NULL_FOR_PRIMITIVESfalla si llega null para un int o double
JsonInclude.Include.NON_NULLomite los null; NON_EMPTY omite además las listas y textos vacíos

Sin el módulo de fechas, escribir o leer un LocalDate lanza InvalidDefinitionException: Java 8 date/time type not supported by default.

8Jackson: el árbol JsonNode

Sin clases: el JSON se carga como un árbol de nodos, parecido al DOM de XML. Útil para leer unos pocos campos o para JSON cuya forma no conoces.

Crear y modificar

path(clave)igual, pero nunca null
has(clave)si existe la clave
asText() asInt() asDouble() asBoolean()valor convertido; admiten un valor por defecto
isObject() isArray() isTextual() isNumber() isNull()de qué tipo es
size()elementos del array o claves del objeto
fieldNames() properties()las claves, o las parejas clave-nodo, de un objeto
put putArray putObject set removemodificar un ObjectNode
add insert set(i, n) remove(i)modificar un ArrayNode

Para ficheros enormes existe la API de streaming: JsonParser (lee token a token, como StAX) y JsonGenerator (escribe), que se sacan de mapper.getFactory().

9Gson: objetos ↔ JSON

Dos métodos: toJson y fromJson. Gson lee y escribe los atributos directamente, aunque sean privados: no necesita getters, setters ni constructor vacío.

toJson(obj)a un String
toJson(obj, writer)a un Writer (o Appendable)
fromJson(texto, Clase.class)de un String o un Reader
fromJson(texto, Type)tipos genéricos con TypeToken
toJsonTree(obj)a un árbol JsonElement
fromJson(jsonElement, Clase.class)de un árbol a un objeto
Atributos transient o staticno se guardan
Atributos a nullno se escriben (salvo serializeNulls())
Claves del JSON que no están en la clasese ignoran sin error
Claves de la clase que no están en el JSONquedan a null, 0 o false
recordfunciona desde Gson 2.10

Gson lanza JsonSyntaxException (JSON mal formado o tipos que no encajan) y JsonIOException. Ambas son no comprobadas: el compilador no obliga a capturarlas.

12org.json: JSONObject y JSONArray

La más simple: un JSONObject es como un Map y un JSONArray como una List. No convierte a tus clases: los datos se copian a mano.

getString getInt getDouble getBooleanvalor; lanza JSONException si falta o no es de ese tipo
optString optInt...valor o uno por defecto
getJSONObject getJSONArrayhijo objeto o array
has(c) isNull(c) keySet()comprobar y recorrer claves
put(c, v) remove(c)añadir o cambiar, y quitar
length() get(i) put(v)en JSONArray
toString() toString(n)a texto, en una línea o con n espacios de sangría
toMap() toList()a colecciones de Java

JSONObject no guarda el orden de las claves: al escribirlo pueden salir en otro orden.

13JSON de una API web

Lo más habitual: pedir datos a un servicio REST con el HttpClient del JDK (Java 11+) y convertir la respuesta con Jackson o Gson.

send lanza IOException e InterruptedException. Muchas APIs devuelven más campos de los que necesitas: usa @JsonIgnoreProperties(ignoreUnknown = true) o desactiva FAIL_ON_UNKNOWN_PROPERTIES.

14Errores habituales

UnrecognizedPropertyExceptionJackson: el JSON trae una clave que la clase no tiene. ignoreUnknown = true
MismatchedInputExceptionJackson: la forma no encaja, por ejemplo un array [...] leído como objeto
InvalidDefinitionException: no CreatorsJackson: la clase no tiene constructor vacío ni @JsonCreator
No serializer found ... no propertiesJackson: atributos privados sin getters; no hay nada que escribir
ClassCastException: LinkedHashMapJackson: lista leída sin TypeReference (con Gson, LinkedTreeMap y sin TypeToken)
Java 8 date/time type not supportedJackson sin JavaTimeModule
Expected BEGIN_OBJECT but was BEGIN_ARRAYGson: el JSON es una lista y se pidió un objeto, o al revés
StackOverflowError al escribirreferencias circulares (padre ↔ hijo): ignora un lado o usa @JsonManagedReference
Números enteros que llegan como 12.0Gson con Map<String, Object>: usa una clase o un TypeToken con el tipo concreto
JSON con comentarios, comillas simples o coma finalno es JSON válido: falla el análisis
Dinero con doubleusa BigDecimal: ver Math
