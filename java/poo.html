Una clase y un objeto

La clase: el molde

El objeto: cada ejemplar

Una clase se escribe una vez; de ella se crean tantos objetos como haga falta, cada uno con sus propios valores. Los atributos van private y se accede a ellos con métodos públicos: eso es la encapsulación.

1Los cuatro pilares

Abstracciónquedarse con lo importante de algo real y modelarlo como clase. Un Alumno tiene nombre y nota; su color de pelo no interesa al programa.
Encapsulaciónocultar los datos dentro del objeto (private) y dejar tocarlos solo a través de métodos que controlan qué se puede hacer.
Herenciacrear una clase a partir de otra (extends): la hija recibe lo del padre y añade o cambia lo suyo.
Polimorfismoun mismo mensaje produce comportamientos distintos según el objeto real que lo recibe.

2Clase y objeto

Clasela definición: qué datos tiene y qué sabe hacer. Es un tipo, como String.
Objeto o instanciaun ejemplar concreto creado con new, con sus propios valores.
Estadolos valores de sus atributos en un momento dado.
Comportamientosus métodos.
Referenciala variable no contiene el objeto, sino una flecha hacia él.

Cuidado: llamar a un método sobre una variable que vale null lanza NullPointerException. Y pasar un objeto a un método pasa la referencia: si el método lo modifica, el cambio se ve fuera.

5Constructores

Por defectosi no escribes ninguno, Java crea uno vacío sin parámetros
Sobrecargavarios constructores con distintos parámetros
this(...)llama a otro constructor de la misma clase
super(...)llama al constructor del padre (ver Herencia)
Validarlanza una excepción si los datos no valen: el objeto no llega a crearse

Cuidado: en cuanto escribes un constructor con parámetros, el vacío por defecto deja de existir y new Punto() no compila. Si lo necesitas, decláralo tú.

6Getters y setters

getAtributo()devuelve el valor
isAtributo()getter de un boolean
setAtributo(valor)cambia el valor; buen sitio para validar
Sin setterel atributo solo se fija en el constructor: solo lectura
Sin getterdato interno que no interesa fuera

No hace falta un getter y un setter para cada atributo: pon solo los que tengan sentido. Una clase sin setters y con atributos final es inmutable, como String. Los IDE los generan solos (en Eclipse: Source › Generate Getters and Setters).

7this y static

thisel objeto actual
this.atributodistingue el atributo de un parámetro con el mismo nombre
static atributocompartido por todos los objetos: contadores, constantes
static métodono necesita objeto: Math.sqrt, Integer.parseInt
static finalconstante: MAYUSCULAS_CON_GUION

Cuidado: desde un método static (como main) no se pueden usar atributos ni métodos de objeto directamente: no hay ningún this. Crea un objeto o haz el método también static.

8Herencia

extendshereda de una sola clase
super(...)constructor del padre; primera línea del constructor
super.metodo()versión del padre de un método
@Overrideavisa al compilador de que estás redefiniendo; te salva de erratas
final classno se puede heredar de ella
final métodono se puede redefinir
Objectla raíz de todas: si no pones extends, heredas de Object

Herencia solo cuando la relación es «es un»: un alumno es una persona. Si es «tiene un» (un coche tiene un motor), usa un atributo: composición.

10Clases abstractas

De una clase abstracta no se pueden crear objetos (new Figura() no compila): sirve para reunir lo común y obligar a las hijas a implementar lo que falta. Si una hija no implementa todos los métodos abstractos, también tiene que ser abstracta.

12equals, hashCode y toString

toString()texto al imprimir o concatenar; por defecto, Alumno@1b6d3586
equals(o)¿valen lo mismo?; por defecto es igual que ==
hashCode()número que usan HashSet y HashMap

Cuidado: si redefines equals, redefine también hashCode con los mismos atributos. Si no, tus objetos se comportarán mal dentro de un HashSet o como claves de un HashMap.

Los IDE generan estos tres métodos automáticamente, y un record ya los trae hechos (ver POO avanzada).

13Paquetes y organización

packageprimera línea del fichero; coincide con la ruta de carpetas
import java.util.List;una clase concreta
import java.util.*;todo el paquete (mejor importar lo que uses)
import static java.lang.Math.PI;una constante o método estático

Una clase public tiene que estar en un fichero con su mismo nombre. Las clases de java.lang (String, Math, System, IO) no hace falta importarlas.
