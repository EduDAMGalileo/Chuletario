Jerarquía de excepciones

Comprobadas: situaciones previsibles del entorno (no existe el fichero, la base de datos no responde). El compilador obliga a tratarlas.

No comprobadas: normalmente errores de programación (un índice mal, un objeto a null). Se arreglan corrigiendo el código, no capturándolas.

1try, catch y finally

trycódigo que puede fallar
catchqué hacer si falla; puede haber varios
finallyse ejecuta siempre, incluso con return dentro del try
e.getMessage()descripción del error
e.printStackTrace()traza completa; útil al depurar

Cuidado: los catch se prueban en orden, así que los más específicos van primero. Si pones catch (Exception e) el primero, los demás nunca se ejecutan (y el compilador lo rechaza).

2Multi-catch

Sirve cuando la reacción es la misma para varios tipos. Los tipos no pueden ser padre e hijo entre sí.

3try-with-resources

Vale para cualquier objeto que implemente AutoCloseable: ficheros, conexiones, Scanner… Evita el viejo finally con close() dentro de otro try.

4Lanzar excepciones

throwlanza una excepción ahora mismo
throwsavisa en la cabecera de que el método puede lanzarla
throw new X("mensaje", causa)conserva la excepción original como causa

Regla práctica: captura la excepción donde realmente puedas hacer algo con ella. Si no, deja que suba con throws.

6Crear tus propias excepciones

Hereda de Exception si quien llama debe tratarla obligatoriamente, y de RuntimeException si es un error de uso que no tiene sentido capturar.

7Leer una traza de error

Se lee de arriba abajo: la primera línea dice qué pasó, y la primera línea at de tu código dice dónde. El número entre paréntesis es la línea exacta del fichero.

8Buenas prácticas

catch vacíonunca: el error desaparece y luego no hay quien lo encuentre
catch (Exception e)demasiado amplio; captura lo que esperas
e.printStackTrace()vale mientras aprendes; en una aplicación real se registra en un log
Mensajes útilesindica el dato que falló, no solo «error»
No para el flujo normalque un usuario escriba mal no debería costar una excepción por letra
Valida antescomprobar if (ruta == null) es más barato que capturar la excepción
Conserva la causathrow new MiError("no pude", e) mantiene la traza original
