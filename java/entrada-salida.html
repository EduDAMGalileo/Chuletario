Las dos familias de clases

Clases de nodo: se conectan al origen o al destino real (un fichero, un array). Clases de filtro: envuelven a otra y le añaden algo, como memoria intermedia o métodos más cómodos. De ahí el estilo de anidar unas dentro de otras.

1Qué clase usar en cada caso

Leer un fichero de texto enteroFiles.readString o Files.readAllLines
Leerlo línea a líneaBufferedReader con readLine()
Escribir textoFiles.writeString o BufferedWriter
Escribir texto con formatoPrintWriter (printf, println)
Leer del tecladoScanner sobre System.in
Copiar un fichero binarioFiles.copy o InputStream / OutputStream
Guardar objetos JavaObjectOutputStream / ObjectInputStream
Datos binarios con tipoDataOutputStream / DataInputStream
Saltar a una posición del ficheroRandomAccessFile
Gestionar rutas, copiar, borrarPath y Files

Si el contenido es texto, usa la familia de caracteres. Si son bytes (imágenes, PDF, ZIP, objetos serializados), la de bytes. Mezclarlas corrompe los datos.

3Reader y BufferedReader

readLine()una línea, sin el salto de línea, o null al acabar
read()un carácter como int, o -1 al acabar
read(char[] buf)un bloque de caracteres; devuelve cuántos ha leído
lines()un Stream<String> con las líneas
ready()¿hay algo preparado para leer?
close()cierra; mejor con try-with-resources
FileReaderlee caracteres de un fichero
InputStreamReaderpuente: convierte bytes en caracteres, con su codificación
StringReaderlee de un texto en memoria; útil para pruebas
BufferedReaderañade memoria intermedia y el método readLine

Cuidado: new FileReader(f) usa la codificación por defecto del sistema. Para asegurar UTF-8: Files.newBufferedReader(ruta), que ya la usa, o new InputStreamReader(new FileInputStream(f), StandardCharsets.UTF_8).

4Writer, BufferedWriter y PrintWriter

write(String)escribe texto
newLine()salto de línea del sistema (BufferedWriter)
println(x)escribe y salta de línea (PrintWriter)
printf(formato, ...)escribe con formato (PrintWriter)
flush()vuelca lo que quede en la memoria intermedia
close()cierra; hace flush antes

Cuidado: si no cierras un writer con memoria intermedia, lo último que escribiste puede no llegar al fichero. Con try-with-resources no tienes que acordarte.

5InputStream y OutputStream

read()un byte, o -1 al acabar
read(byte[] buf)un bloque; devuelve cuántos bytes ha leído
readAllBytes()todo el contenido
write(byte[] b)escribe un bloque
write(b, inicio, longitud)escribe una parte del bloque
transferTo(salida)vuelca un stream en otro
available()bytes que se pueden leer sin bloquear

Los Buffered… agrupan las lecturas y escrituras para no ir al disco byte a byte. Con ficheros grandes la diferencia de velocidad es enorme.

6Scanner

nextLine()el resto de la línea
next()la siguiente palabra
nextInt() nextDouble()el siguiente número
hasNextLine() hasNextInt()comprueba antes de leer y evita la excepción
useDelimiter(";")cambia el separador
close()cierra el origen

Cuidado: Scanner es cómodo pero lento con ficheros grandes: para eso, BufferedReader. Y recuerda el salto de línea que deja pendiente nextInt().

8Serialización de objetos

Serializableinterfaz sin métodos: marca la clase como guardable
serialVersionUIDversión de la clase; si no coincide al leer, falla
transientcampo que no se guarda (contraseñas, datos calculados)
writeObject / readObjectescribir y leer el objeto
ClassNotFoundExceptionla lanza readObject: hay que capturarla

El fichero resultante solo lo entiende Java, y deja de valer si cambias la clase. Para guardar datos que vayan a durar o que tenga que leer otro programa, usa CSV, JSON o XML.

9RandomAccessFile

"r" "rw"modo de apertura: solo lectura o lectura y escritura
seek(posicion)se coloca en ese byte
getFilePointer()en qué byte está
length()tamaño del fichero
setLength(n)recorta o amplía el fichero

Es el único que permite leer y escribir en cualquier punto sin recorrer el fichero entero. Se usa con registros de tamaño fijo: si cada registro ocupa 64 bytes, el registro n está en seek(n * 64).

10Codificación de caracteres

Desde Java 18 la codificación por defecto es UTF-8 en todas las plataformas, así que casi nunca hay que indicarla. Solo hace falta cuando el fichero viene de otro sistema. Si aparecen símbolos raros donde había tildes, el problema es este.
