La idea

Java puede lanzar otros programas del sistema operativo (un comando, un script, otro ejecutable) y comunicarse con ellos. La herramienta recomendada es ProcessBuilder; cada programa lanzado es un objeto Process.

Las piezas

ProcessBuilderconfigura y arranca el proceso
Processel proceso ya en marcha
Runtime.execla forma antigua, más limitada

1Proceso, no hilo

Conviene no confundirlos: un proceso es un programa independiente del sistema operativo; un hilo es una línea de ejecución dentro de tu propio programa.

Procesootro programa (un .exe, un comando); memoria separada
Hiloejecución concurrente dentro de tu JVM; memoria compartida
Esta chuletalanzar procesos externos desde Java
Paquetejava.lang (Process y ProcessBuilder no necesitan import)

Lanzar procesos sirve para invocar herramientas del sistema (git, ffmpeg, un script) desde una aplicación Java, cuando no hay una librería que lo haga directamente.

2ProcessBuilder

Cada argumento va por separado (no una cadena única): así se evitan problemas con espacios y comillas.

new ProcessBuilder(cmd, arg...)el comando y sus argumentos, uno por uno
directory(File)carpeta desde la que se ejecuta
environment()Map con las variables de entorno (editable)
redirectErrorStream(true)junta la salida de error con la normal
inheritIO()usa la consola del programa padre
start()lanza y devuelve el Process

Pasar los argumentos separados es más seguro que montar una sola cadena: no hay que preocuparse de escapar espacios ni caracteres especiales del shell.

3Leer la salida

La salida del proceso se lee desde su input stream (lo que el proceso escribe, tu programa lo lee como entrada).

getInputStream()lo que el proceso escribe en su salida estándar
getErrorStream()su salida de error
getOutputStream()para enviarle entrada al proceso

Ojo al nombre: getInputStream() es lo que lees del proceso (su salida), no lo que le mandas. Se llama así desde el punto de vista de tu programa. Ver clases de entrada/salida.

4Esperar y código de salida

waitFor()bloquea hasta que termina; devuelve el código de salida
waitFor(t, unidad)espera como mucho ese tiempo; true si terminó
exitValue()el código de salida (si ya terminó)
Código 0convenio: éxito; distinto de 0, algún error

Interbloqueo clásico: si el proceso genera mucha salida y no la vas leyendo, su buffer se llena y se queda parado, y tu waitFor() nunca vuelve. Lee la salida (sección 3) antes o a la vez que esperas.

5Runtime.exec

La forma clásica, anterior a ProcessBuilder. Funciona, pero es más propensa a errores (parte la cadena por espacios).

Prefiere ProcessBuilder: da más control (carpeta, entorno, redirección) y evita el problema de exec("mi programa"), que parte mal las rutas con espacios. Pásale siempre un array de argumentos, no una cadena.

6La API Process

isAlive()¿sigue en marcha?
pid()el identificador de proceso del sistema
destroy()pide que termine (suave)
destroyForcibly()lo mata a la fuerza
onExit()un CompletableFuture que completa al terminar
info()datos del proceso (comando, inicio, usuario)
ProcessHandle.current()el propio proceso Java; allProcesses() lista todos

onExit() permite reaccionar cuando el proceso acaba sin bloquear el hilo: p.onExit().thenRun(() -> ...).

7Windows vs Linux

El mayor escollo al lanzar procesos es que el comando cambia según el sistema. Java corre en ambos, pero el programa que invocas no.

IntérpreteWindows: cmd.exe /c · Linux/Mac: /bin/sh -c
EjecutablesWindows: .exe, .bat · Linux: sin extensión, con permiso +x
RutasWindows: C:\ruta (barra invertida) · Linux: /ruta
SeparadoresFile.separator y File.pathSeparator según el SO
Fin de líneaWindows: \r\n · Linux: \n (System.lineSeparator())

Necesitas el intérprete (cmd /c, sh -c) cuando quieres tuberías, redirecciones o comandos internos del shell; para un ejecutable suelto, llámalo directamente. Comandos de cada sistema en Comandos de Linux.

8Buenas prácticas

Argumentos separadosnunca montes una sola cadena con datos del usuario (inyección de comandos)
Lee la salidaconsume los streams para no bloquear el proceso
Pon un timeoutwaitFor(t, unidad) y destroyForcibly() si se pasa
Comprueba el códigoun exitValue() distinto de 0 es un fallo
Cierra los streamsusa try-with-resources (ver Excepciones)
No asumas el SOdetecta os.name o usa librerías multiplataforma

Inyección de comandos: si construyes el comando concatenando texto del usuario y lo pasas a un shell, pueden colar órdenes propias. Pasa siempre los argumentos por separado y evita el intérprete si no lo necesitas. Relacionado: shells.
